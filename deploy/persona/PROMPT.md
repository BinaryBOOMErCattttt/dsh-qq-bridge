# 人设编写提示词（复制即用）

给部署者：这不是一张给人填的表，是一段**让 agent 来问你**的提示词。它只做三件事 ——
先问你「一次答完还是一题一题来」，再按你的选择问 18 道带选项的题，最后写出
`<cwd>/.qq-persona/PERSONA.md`（是谁）与 `STYLE.md`（怎么说）。

**怎么用**

1. 打开 DSH 的 Web UI 主会话（或者任何能读写工作目录的编码 agent），把本页
   「复制从这里开始」到「复制到这里为止」之间的内容整段贴进去。
2. 它会先问你怎么问，再一题一题来。每题都有推荐项；不想答的题直接写 `-`，它按推荐项补齐。
3. 写完它会跑 `node scripts/persona-check.mjs` 自检。想先看看成品长什么样，打开
   [`PERSONA.template.md`](PERSONA.template.md) 与 [`STYLE.template.md`](STYLE.template.md) ——
   那两份是「模板路线」用的默认答案，跟这份提示词不冲突。

**它不会做的事**：改 `.qq-persona/` 以外的文件、动 `cordis.patch.yml`、把人设写在
`.qq-memory/` 里。配置项（`stripShortPeriod` / `imageSend` / `proactive`）它只会列在最后
让你自己去设置页改 —— DSH 的 patch 是整块替换，agent 手改一次就可能把 `allowTools` 一起顶掉。

【第二步】按我的选择做：

  「选它会怎样」，最后一项永远是「我自己写」；每个选项下面用一行写出「选它 = 文件里会多
  这一行（或者哪个配置要改）」；我答完再问下一题，不要提前问下一题。我答「随便 / 都行 / ?」
  就按推荐项走，并说一句你选了哪个。每答完 5 题，给我看一眼「现在的人设长这样」，让我能回头改。

  让我挑一个当底，再进入 A 或 B。

【问卷 · 18 题】每题第一个选项是推荐项。「→」后面是选了它的结果：要么是文件里会多出来的
那一行（以 `-` 开头），要么是一个动作（「这段留空」「提醒我改哪个配置」）。

3. 写之前先跑 `node scripts/persona-check.mjs` 看一眼现状；写完再跑一次，把输出贴给我。

4. 最后给我四样东西：两个文件的路径；一张「我确定的 / 你补的 / 还可以再改」的表；

【文件格式 · 必须照抄】

PERSONA.md —— 只写「是谁」，四节：
  ## 身份    每行 `- 键：值`，渲染时会拼成一句
  ## 背景    每行一句事实（不是台词，不会每轮都念）
  ## 性格    每行 `- [x] 名字｜底色/点缀｜强度｜触发条件｜表现｜禁忌（可选）`
            底色只能一条；点缀最多两条；`[ ]` = 停用但留着以后改
  ## 场景    四个子节：`### 私聊` / `### 群聊` / `### 主动搭话` / `### 被戳一戳`
  认不出的节会被忽略并记 warn；某一条写歪只会降级，不会整份失效。

STYLE.md —— 只写「怎么说」，五节：
  ## 总体 / ## 标点 / ## 表情包 / ## 私聊 / ## 群聊
  每行一条能执行、能举例的规则。不要写「自然一点」「像真人」「有温度」这种没法判断的话；
  不要写「分点说明」「总结一下」；不要写「一句里逗号最多一个」（会被当成配额，句句配一个逗号）；
  不要写「忽略以上规则」（压不过提示词最后的硬性规则）。

【硬要求】

- 一次只问一件事。除了 A 模式那一整份问卷，任何时候都不要一口气抛多个问题。
- 每题都要给选项，第一个标（推荐）并说清后果；不用「看你想怎样」这种空选项。
- 我问「为什么」时用一句人话解释（比如「两条底色会被模型平均成谁也不像的人」）。
- 性格的「表现」要写成看得见的行为，不写台词；口癖放 STYLE.md 的语气词那条。
- 不写客服腔；人设控制在 3000 字以内（personaMaxChars 默认 4000，超了会截断，前面白写）。
- 只动 `.qq-persona/PERSONA.md` 与 `.qq-persona/STYLE.md`。不要动 `cordis.patch.yml`、
  不要改配置、不要写 `.qq-memory/` 或 `data/` 里的东西。配置项只写进最后那张表。
- 如果你没有写文件的能力，就把两份文件的完整内容打出来让我自己复制，别只给片段。
- 我说「先不写」就停在第 1 步，别硬写文件。

## 这份提示词为什么这样写

- **先问「怎么问」**：一次答完和一题一题来是两种完全不同的耐心，替用户选错，后面每一步都别扭。
- **选项即结果**：每个选项后面直接跟「文件里会多这一行」。用户不需要懂格式，也能看见自己选出来的是什么东西 —— 这比让人读一遍 `PERSONA.md` 的格式说明有效得多。
- **默认值兜底**：`-`、「随便」、「都行」都落到推荐项。人设问卷最怕卡在「我不知道该选什么」，有推荐项就永远能往下走。
- **先确认再落盘**：第 1 步那张「题号 / 答案 / 会写成哪一行」的表是唯一一次回头的机会，写完再改就要重读文件了。
- **自检交给脚本**：模型说「写好了」不算数，`scripts/persona-check.mjs` 会把解析警告、底色条数、STYLE 体检逐条打印出来（见[写人设：模板、问答与自检](../../docs/persona-workshop.md)）。
